# 游戏、关键词与竞品验证

## 找源头

- Steam、Roblox、Google Play、App Store、itch.io 查游戏或更新。关注官方公告、同一开发商的后续作品、游戏资讯网站、主播和讨论社区。用旧热点回查谁最早发布，再订阅这些资讯源的 sitemap。同行攻略站的 sitemap 适合发现已有人做的需求，可能已经错过首发窗口。
- 从 FindNews 或 Trends 找候选，再看 YouTube、TikTok 和 Discord 的实际讨论。检查讨论内容是新游戏、更新、回流、模组，还是同名词。游戏相关信号与可承接的搜索需求需要独立验证。
- 哥飞小课堂的竞品 sitemap 方法：选一批持续更新的游戏站，按新增 URL 提取标题或游戏名，再用 Trends 与搜索结果判断是否真有新需求。站点地图中的发现时间或 lastmod 仅作线索。可结合竞品主要页面、托管子域名和现有站关键词滚动找同类站；模组生态也能挖出特定地图、版本、依赖或报错的需求。
- 从托管平台找新站时，用有覆盖的报告查近期发现的自然落地页，记录具体子域名或 URL，再提取热门关键词并回查趋势与竞品。若工具只显示平台根域名，按具体子域名另查。平台日期、发现时间和项目上线时间分别记。
- 已知游戏名时，用 `game`、`guide`、`wiki`、`codes`、`map`、`tier list`、`characters`、`items`、`recipes`、`walkthrough`、`calculator`、`tracker`、`release time`、`countdown` 扩词。Google 自动补全可用 A–Z 扩展，社区原话和 Trends 上升查询也可补充。如果还没有游戏名，可从平台、品类或活动词入手。AI 可归类候选词，游戏状态和词意需复核。

## 验证强度与竞争

- 用同地区的 7、30、90 天 Trends 判断事件尖峰、周期性回升或持续需求。截图虚线或未完整时段单独处理。补全顺序和 FindNews 重复信号不能用作搜索量。Semrush 等工具的量、KD 和点击估算按数据库、地区及日期解读。
- 查核心词及 2–3 个玩家问题的搜索结果。记下已有页面能否直接回答、版本是否过时、是否有原创图解、工具是否可用。关注独立小站是否能进入前排。老域名或低 KD 都不直接决定竞争难度，`allintitle:` 仅是辅助手段。
- 查竞品的主要页面和自然排名，以具体 URL 为单位区分整站访问与页面点击。域名注册时间、网站上线时间、文章发布时间分别核查。`github.io`、`vercel.app` 等托管子域名用页面快照、仓库首次提交或可核实的发布记录辅助判断。
- 某页面点击回撤时，对照同地区关键词趋势、发售／赛程日期和排名变化。活动过后需求下降，可围绕下一轮布局；只有该页下降，检查其答案过期或竞争分流。近期体量与历史均值差距大时标出持续性风险。

输出候选比较时注明游戏及版本、词组和意图、需求证据、现有结果的缺口、内容成本与建议动作。证据薄时可先观察或做现有站内页，避免仅凭热点另开站。
