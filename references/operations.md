# 游戏攻略页面、上线与复盘

## 页面选择

| 玩家任务 | 页面形态 | 首屏优先给出什么 |
|---|---|---|
| 怎么玩、怎么过关、怎么领 | Guide / Walkthrough | 短答案、前提、版本和步骤 |
| 查物品、角色、地图、机制 | Wiki 条目或索引 | 数据、获取方式或分类入口 |
| 查兑换码 | Codes 页 | 已核验状态、兑换步骤、核验时间 |
| 查强度和搭配 | Tier List / Build Guide | 适用模式、版本、评分依据 |
| 什么时候开服、发售或举办活动 | 时间说明或倒计时 | 官方时间、地区／平台、本地时区 |
| 反复算价格、配装、赛果或刷新 | 计算器、模拟器或追踪工具 | 工具、输入条件、结果和数据来源 |

攻略优先自己试玩、用官方资料核验，社区视频可提供线索。图解用实际游戏版本与原创标注，标出读者会卡在哪里。给关键图片写描述性替代文字。可在同一站用总览串接条目、工具与相关攻略；只需少量资料时可先做轻量指南。明确非官方关系，尊重素材使用条件。

只有官方时间足够明确才做确定式倒计时；只有日期时说明时区或时间待公布。刷新工具基于玩家观测时标明输入来源、估算范围和失效条件，只有可验证的授权数据源才能宣称实时通知。比赛模拟器要注明适用赛季和规则，赛段结束后适时更新或存档。

如果玩家要理解解法，可以做交互讲解工具。知识库的数独练习从手动输入和规则求解出发，再扩展逐步解释、截图识别、语音等入口。应用到其他解谜游戏时，先验证规则与答案，让讲解基于可复现的解法，按实际需求决定是否加识别或语音。

## 上线、扩展和推广

- 从一个最强需求页起步，或用首页加 3–5 个独立意图页作第一版。模板复用导航、页面结构、部署和数据检查即可；保留各页具体答案、图解和工具功能。
- 标题与主标题围绕页面任务，站内链接指向下一步要查的内容。图片可用图解、标注地图或原创对照表。提交 sitemap 后在 GSC 核对索引、查询、页面、曝光和点击。已经出词的页面小幅调整标题时记录日期，再看对应查询变化；先保留原有意图。
- 优先修正有曝光但答案不完整的页，再补真正有独立答案的内页。跟踪游戏生命周期，借助低成本试验判断要不要加 Wiki 条目、工具、编辑维护或其他语言。做多语言前单独验证当地玩家的词、页面结果和维护能力。
- 做可以被引用的资料，例如实测步骤、对照表或时间工具。社区规则允许时先回答问题，再透明附上对应内页。可把补充信息提供给相关攻略作者，由对方自行决定是否引用。避免刷评论、购买传递排名信号的链接或大量互换链接。评估外链时兼顾实际引荐访问和内容相关性。
- 复盘记录候选词、上线时间、GSC、内容更新成本和去留理由。按数据决定加深或暂停。广告和付费工具是可选商业模式，评估时看实际数据，不以竞品估算访问量推断真实收入。
